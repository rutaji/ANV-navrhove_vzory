\section{Paterny}
\subsection{Factory/ simple Factory}
Jednoduší forma Factory Method. Factory method používá jeden objekt továrny pro vracení jedné implementace, zatímco
simple Factory vrací vše jednou metodou anebp několika metodami, ale pořád vše v jednom objektu.
 Výhody:
\begin{itemize}
  \item Snižuje počet tříd a Interafaců.
\end{itemize}
Nevýhody:
\begin{itemize}
  \item Uzavřené k rozšíření narozdíl od Factory method.
\end{itemize}

\subsection{Factory Method}\label{Factory Method}
Umožnuje vytvářet objekty pomocí metody namísto konstruktoru. Vytvářené objekty sdílí stejný interface, 
což umožnuje metodě vracet různé objekty. Metoda budto může vracet různé objekty podle dodaných parametrů, anebo můžeme od Factory (třída, která obsahuje faktory metodu)
dědit další factory, které vrací různé objekty. Používat interface pro továrnu umožnuje ji lechce vyměnit při změně kódu anebo při testování.
Umožnuje mít veškerý kód pro vytváření objektu na jednom místě a lechce měnit jaký objekt bude vytvořen na více místech v kódu.
\medskip \newline %
Výhody:
\begin{itemize}
  \item Snižuje propojení mezi třídami.
  \item Single Responsibility Principle.
  \item Kód je jednoduše rozšířitelný. Můžeme přidávat nové produkty a továrny bez změny předchozího kódu. Knihovna používající Factory method je mnohem více rozšířitelná.
  \item Snižuje duplikaci kódu okolo vytváření objektu.
  \item Umožnuje vracett už existující instanci namísto vytváření nové.
\end{itemize}
Nevýhody:
\begin{itemize}
  \item Továrna může vracet pouze objekty dědíci daný interface.
  \item Vytváření velkého množství interfaců a podtříd.
\end{itemize}
\medskip
\subsubsection{Relations with Other Patterns}
\begin{itemize}
  \item Factory method se vyvíjí do Abstract Factory, Prototype, Builder.
  \item Factory method se používá k vracení různých Iterátorů.
  \item Factory method je druh Template Method. Zároveň Factory může být součástí větší Template Method.
\end{itemize}

\subsection{Singleton} \label{Singleton}
Používá se pokud je v programu potřeba aby existovala jediná instance určité třídy. K této třídě také poskytuje globální přístup. Tím porušuje zákon Single Responsibility, jelikož řeší 2 věci najednou.
Často se používá u konfigurací, přístupu k souboru nebo databázi. Jedná se o globální stav a všechy objekty na které obsahuje reference jsou také globální stav =$>$ je těžké je mockovat v testech. Podobné problémy jako globální proměné. 
Singleton (velké S) je patern, zatímco singleton (malé s) je třída která by měla míti pouze jednu instanci.
\medskip \newline 
%
Výhody:
\begin{itemize}
  \item Lazy vytváření.
  \item Pouze jeden existující objekty.
  \item Jednoduché řešení (na začátku).
\end{itemize}
Nevýhody:
\begin{itemize}
  \item Poskytuje globální přístup k proměným, praktivké, ale velmi nebezpečné.
   Může zakrývat špatný návrh kódu. Může vytvářet zbytečne velké závislosti mezi třídami.
  \item Vyžaduje úpravu pro multi-thread safety.
  \item Pokud možno je lepší používat dependency injection.
  \item Špatně se testuje. Jelikož je singleton měnící se statická hodnota, tak si zachová 
  změny mezi testy (\href{https://testing.googleblog.com/2008/08/by-miko-hevery-so-you-join-new-project.html}{Singletons are pathological liars.}). Je potřeba ho mezi testy resetovat mezi testy, testy také nemohou běžet paralerně. Stejně tak mokování může být obtížné.
  \item Zvětšuje propojení mezi třídami.
  \item Může skrývat co se děje v kódu a skrývat propojení mezi třídami.
\end{itemize}
\medskip

Častou chybou je následující kód, ve kterém se snažíme vytvořit třídu CreditCard. 
Jenže třída CreditCard nefunguje pokud nejdříve nespustíme OfflineQueue.init() a ta potřebuje nejdříve spustit CreditCardProcessor.init();. 
V kódu nic nenaznačuje, že by na sobě třídy byli závislé jelikož je to skryté.  
\begin{lstlisting}
CreditCardProcessor.init();
OfflineQueue.init();
CreditCard c =  new CreditCard(  "1234 5678 9012 3456", 5, 2008);
c.charge(100);
Database.init(); 
\end{lstlisting}
Je lepší závislosti ukázat tím, že je budeme vyžadovat předat k operaci. 
\begin{lstlisting}
  Database db = Database();
  OfflineQueue q = OfflineQueue(db);
  CreditCardProcessor ccp = new CreditCardProcessor(q);
  CreditCard c =  new CreditCard(  "1234 5678 9012 3456", 5, 2008);
  c.charge(ccp, 100);
\end{lstlisting}
